흐름

알려는 것: 화면은 Redis만 읽는다. ClickHouse seed는 이력 테이블용이고 대시보드에는 나오지 않는다.

Step 0 · 한 번만

0. 한 번만 설정

알려는 것: Docker 런타임과 .env, 의존성. 이미 했으면 건너뛴다.

저장소 루트에서
colima start --cpu 4 --memory 6
docker context ls            # colima 줄에 * 가 있어야 한다
cp infra/env.example .env    # CLICKHOUSE_PASSWORD 를 채운다 (필수)
pnpm install
  • .env는 커밋하지 않는다.
  • KAFKA_BOOTSTRAP은 넣지 않는다. MVP1은 Kafka 없이 돈다.
  • jq가 있어야 한다 (make migrate, make health).
Step 1 of 6

1. 저장소 띄우기 (ClickHouse, Redis)

make up
docker compose -f infra/docker-compose.dev.yml --env-file .env ps   # 둘 다 healthy
make migrate

선택: ClickHouse에 mock 이력을 넣는다. 대시보드만 볼 거면 건너뛰어도 된다.

docker exec -i clickhouse-dev sh -c \
  'clickhouse-client --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" -d "$CLICKHOUSE_DB" --multiquery' \
  < mocks/seed-clickhouse.sql

docker exec clickhouse-dev sh -c \
  'clickhouse-client --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" -d "$CLICKHOUSE_DB" \
   -q "SELECT venue, count() FROM pred_orderbook_ws FINAL GROUP BY venue"'
  • seed를 두 번 넣어도 FINAL 조회에서는 같은 키가 하나로 접힌다.
Step 2 of 6

2. writer와 api 띄우기

make start
  • writer는 MOCK_SOURCE=1로 뜨고, api는 :3001에 뜬다.
  • 로그는 logs/writer.jsonl, logs/api.jsonl에 쌓인다. pid는 logs/*.pid에 있다.
  • 이미 떠 있으면 다시 띄우지 않고 "already running"을 찍는다.
Step 3 of 6

3. 대시보드 열기

pnpm --filter @repo/web dev
# 열기: http://localhost:5173

Makefile에는 이 단계가 없다. 새 터미널에서 실행하고 Ctrl+C로 끈다. Vite가 /api를 localhost:3001로 넘긴다.

화면에서 볼 것정상
venue 선택kalshi, polymarket 둘 다 고를 수 있다
오더북두 venue 모두 값이 계속 바뀐다 (티커당 약 400ms)
feed 배지mock
freshness 배지fresh. stale_ms가 5,000ms를 넘으면 stale
Step 4 of 6

4. 명령으로 확인

api 응답 (두 venue)
curl -s localhost:3001/api/orderbook/kalshi/MOCK_KXBTCD-26SEP22-B112000 | jq '{feed, stale_ms}'
curl -s localhost:3001/api/orderbook/polymarket/MOCK_POLY_71321045679252212594626385532706912750332728571942532289631379312455583992563 | jq '{feed, stale_ms}'
curl -sN localhost:3001/api/stream     # SSE. 이벤트가 계속 오면 정상, Ctrl+C

정상: feed가 "mock", stale_ms가 5000보다 작은 숫자다. 없는 티커는 404다.

Redis
docker exec redis-dev redis-cli KEYS 'ob:*'
docker exec redis-dev redis-cli SCARD ob:index        # 2 이상
docker exec redis-dev redis-cli TTL writer:heartbeat  # 60 이하
health check와 로그
make health                       # 4개 단언, 모두 통과하면 exit 0
jq -e 'type=="object"' logs/writer.jsonl logs/api.jsonl > /dev/null && echo "모든 줄 JSON"
make tail-logs                    # 실시간으로 보기, Ctrl+C

health check 4개: writer와 api가 살아 있다 · Kafka 소켓 0개 · 로그 전 줄 JSON · writer 마지막 로그가 15초 안.

Step 5 of 6

5. 일부러 끊어 보기 (freshness)

알려는 것: writer가 죽으면 화면이 stale로 바뀌는지. MVP1 EXIT 기준이다.

make stop-writer
# 약 5초 뒤 화면의 freshness 배지가 stale 로 바뀐다
curl -s localhost:3001/api/orderbook/kalshi/MOCK_KXBTCD-26SEP22-B112000 | jq .stale_ms   # 계속 커진다
make health        # 단언 1(writer 생존)이 실패해야 정상

make start-writer  # 되돌리기: 배지가 fresh 로 돌아온다
Step 6 of 6

6. 끄기

# 웹: 그 터미널에서 Ctrl+C
make stop     # writer, api
make down     # ClickHouse, Redis 컨테이너 (데이터 볼륨은 남는다)
  • make down에 -v를 붙이지 않는다. 볼륨을 지우면 ClickHouse 데이터가 사라진다. 볼륨 초기화는 소유자가 정한다.
  • pid 파일은 지우지 않아도 된다. 다음 make start가 덮어쓴다.
